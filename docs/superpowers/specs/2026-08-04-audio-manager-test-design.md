# AudioManager 测试基座设计

## 目标

提供一个开箱可运行的独立测试场景，覆盖当前 AudioManager 的主要使用方式，并让后续替换正式音频时只需修改 Godot 资源配置。

## 方案

- 测试数据放在 `data/audio/test/`，每个音效或 BGM 使用独立 `.tres`。
- 测试 WAV 放在 `Art/Audio/Test/`，只用于验证播放流程，不进入正式配置。
- `Scenes/Audio/Test/audio_manager_test.tscn` 在运行时把测试资源注入 Autoload，并在退出时停止播放。
- 场景提供按钮，覆盖字符串和 enum/id 调用、临时音量、2D 定点与跟随、循环停止、同名打断、每帧限播、BGM 淡入淡出、双通道开关、长度查询和前奏结束后切换。
- 自动化冒烟测试使用同一批真实资源，检查配置索引、播放入口、对象池复用、2D 跟随、BGM 查询和排队接口。

## 边界

- 不修改正式 `audio_manager.tscn` 的音频列表。
- 不增加外部配置表或第三方测试框架。
- 测试音采用简单合成波形，仅用于确认行为，不代表最终听感。
- 无缝衔接仍要求制作侧保证前奏尾部和正式曲开头在节拍及波形上可连接。

## 验证

- Godot 无头模式可导入项目并运行自动化测试场景，退出码为 0。
- Godot 无头模式可加载交互测试场景，无脚本解析错误。
- `git diff --check` 无格式错误。
